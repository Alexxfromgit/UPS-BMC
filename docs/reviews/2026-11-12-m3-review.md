# M3 review: battery health estimation and guided runtime test

- Commit: `000da40` (main)
- Date: 2026-11-12
- Scope: `ups-analysis` `health.rs`, `runtime_test.rs`, test tagging in `tracker.rs`; `ups-model` `health.rs`/`event.rs`; store migration v4 and `battery_installed`; collector `api.rs`/`ingest.rs`/`poller.rs`; sim aging; UI `health_view.rs`, `client.rs`, `main.rs`, `view.rs`, the Battery health tab in `app.slint`; ADR-0004.
- Method: read-only. I read the code and ran `cargo test --workspace` (all pass). I also built a scratch probe crate outside the repo with path dependencies on `ups-analysis`/`ups-model` and ran `health::assess` on the edge cases below. I did not change any source file, and I did not touch the UPS.

## Summary

The estimator matches ADR-0004 point by point: the usable-discharge filter, `min(3, n/2)` / `min(3, n−b)` grouping, medians, the 100 % cap, confidence levels and downgrades, verdict thresholds and age reasons. The test state machine is small and correct for the normal case. Nothing in M3 writes to the UPS.

The main problems:

- **Health can swing between metrics.** The comparison metric is decided over all discharges, and it changes when the user enters a load estimate. That silently moves the baseline. With 7 discharges the probe reports 60 % (Aging); after the 8th it reports 100 % (Good).
- **A load estimate raises confidence without adding information.** One constant estimate changes nothing in the ratio, but it skips the "load unknown" downgrade.
- **The runtime-test state lives only in memory.** If the collector restarts mid-test, nobody is told to plug the UPS back in.
- **The UI re-sends a cached health report up to 60 s old.** During an outage it does so every second, which undoes a fresh install-date change and overwrites the date field.

Counts: 0 High, 6 Medium, 6 Low.

## Checked and fine

- **ADR-0004 §1–6 agree with the code.** Filter: start ≥ 80 %, ≥ 5 points, ≥ 60 s, start and end observed, ongoing excluded. Groups `b = min(3, n/2).max(1)` and `r = min(3, n−b).max(1)` never overlap (`b + r ≤ n`). Medians with an even count use the midpoint. Health is clamped to 0–100, but `relative_pct` isn't (correct for the trend). Confidence is High ≥ 6 / Medium ≥ 4, with the strong-discharge downgrade and the load downgrade; the spread check is guarded by `powers.len() >= 2`. Verdict thresholds 60/80, RB overrides, Unknown below 2. Age reasons at 3 and 4 years.
- **Capacity and full-runtime projection.** `capacity_wh × 3600 / reference W` with the reference taken from the recent group; all recent members have capacity when `by_capacity`. The single-discharge case (`recent = used`) is handled.
- **0 and 1 discharge, no power at all, ongoing outages.** These give Unknown or no confidence, a correct "Needs N more" message, and no panic. The empty-input median returns `None`.
- **`age_months` and battery age.** Future or same-day dates clamp to 0; the API rejects future installation dates (`api.rs` uses `Local::now()`); the date parses as `YYYY-MM-DD` or `DD.MM.YYYY` in the UI.
- **Arming a test.** It needs a fresh reading (< 30 s), mains power, ≥ 95 % charge and a stop level in 20–90 (NaN is rejected; JSON can't carry it anyway). A second arm is refused. Expiry after 30 min is checked against the snapshot time.
- **Test tagging order.** `test.on_snapshot` runs before `analysis.set_testing`/`on_snapshot`, so the first on-battery sample is tagged. The Finished summary finds the outage closed on the same sample. LB raises RestorePower early. Reminders follow every 2 min (`>=`). A mains return in the Running or RestorePower phase ends the test.
- **Concurrency.** Test start and cancel and the installation date go through `ask_ingest`, so the ingest thread stays the only writer and the only owner of the test state. `/health` reads on a separate read-only WAL connection, and `outages_since(DESC, limit)` is re-sorted by `assess`.
- **Migration v4** adds `runtime_test INTEGER NOT NULL DEFAULT 0`, and the column index (17) and the INSERT/UPDATE placeholders line up. `battery_installed` round-trips through `meta`. A resumed open outage keeps its tag.
- **Safety.** None of the M3 paths (`/battery/test`, `/settings/battery`, `RuntimeTest`, sim) send anything to the UPS. The poller's write path is still only the beeper. The new POST endpoints call `reject_browsers`.
- **UI.** `thread_local!` (`TREND`, `SHOWN_INSTALLED`) is only touched on the Slint event-loop thread (`apply_health` and `render_trend` run from `invoke_from_event_loop` or callbacks). The trend clamps x and y and draws guides only when there is data. `STOP_LEVELS` matches the ComboBox model (default index 3 = 50 %). Collector errors are shown via `request_then_refresh`.
- **Sim aging.** Drain rises 2 %/cycle, capped at +10 %. The runtime estimate stays consistent with the new-battery drain, and the charge never goes negative at the cap (11 % at cycle 5).
- `cargo test --workspace` passes, and `cargo clippy --workspace --all-targets` reports no warnings.

## Resolution (2026-11-12)
All findings fixed in the main session. 140 workspace tests pass; clippy, rustdoc and cargo-deny are clean. ADR-0004 updated.
