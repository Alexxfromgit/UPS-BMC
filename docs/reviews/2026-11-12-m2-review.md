# M2 code review: outage analysis and monthly reports

- Date: 2026-11-12
- Commit reviewed: `000da40` (M2 code as it stands after M3; M3-only logic is out of scope)
- Scope: `crates/ups-analysis/src/{tracker,coverage,stats,report,format}.rs`, `crates/ups-model/src/outage.rs`, `crates/ups-store/src/analysis.rs` + migrations in `crates/ups-store/src/lib.rs`, `apps/ups-collector/src/{outages,api}.rs` (outages/stats/report), the Outages/Reports parts of `apps/ups-bmc` (`view.rs` `outages_view`, `client.rs`, `main.rs` `wire_reports`/`save_report`, `ui/app.slint`), `apps/ups-collector/tests/e2e_sim.rs`
- Reviewer: independent read-only review session. No source file was changed; this report is the only file added.

## Summary

The M2 design is sound: interval accounting is consistent between the outage tracker and daily coverage, both split at real local-midnight instants (so 23 h / 25 h DST days are right), the HTML report escapes every device-supplied string, the CSV contains no user- or device-controlled text, and the report file name is built from the parsed year/month only. `cargo test -p ups-analysis -p ups-store -p ups-model` passes (46 tests), and `cargo clippy -p ups-analysis -p ups-store --all-targets -D warnings` is clean.

The real problems are in the outage state machine and its restart handling:

- **M2-1 (High):** the flapping merge practically never fires on real hardware. A short outage that leaves the charge at ≥ 99 % is closed *and* marked recharged on the same sample, so the "recharging" outage the merge depends on is already gone.
- **M2-2 (Medium):** after a flap merge or a collector restart, the stored averages count as a single sample, so avg load/power are dominated by the last few seconds.
- **M2-3 (Medium):** after a restart, an older outage whose recharge was *interrupted* by a later outage is resumed as "recharging" and gets a bogus `recharged_at`.
- **M2-4 (Medium):** recharge times and on-battery continuity are taken across monitoring gaps without any "not observed" marker.

I reproduced M2-1 through M2-4 and M2-5 with scratch tests against a copy of the repo (`review-probe` crate, see "How this was checked").

## Checked and fine

- **Interval accounting:** the outage duration (first OB sample → first OL sample) matches the coverage rule "an interval takes the state of the sample that began it". The energy integral skips the interval before the first OB sample and caps steps at `max_step`.
- **End/start hidden in a gap:** `end = last OB sample` and `end_latest = first sample after the gap`; `start_earliest = last sample before the gap`. These match the `Outage` docs, and the tests cover them.
- **Out-of-order and duplicate samples** (`ts <= last`) and **unknown status** are ignored by the tracker, and `last` isn't advanced by a status-less sample.
- **Daily coverage** splits at the actual local-midnight instant of each day (`from_local_datetime(..).earliest()`), so 23 h and 25 h DST days get the right number of seconds. `period_stats` computes the period length from real instants as well. Month boundaries come from `month_range` (leap years tested).
- **Coverage after a restart:** `resume(last_sample)` plus the final `flush` on shutdown means no double counting, and at most ≤ 10 s of increments is lost on a crash.
- **Availability** is `(monitored − on_battery) / monitored`, clamped, `None` when nothing was monitored. Coverage % is clamped to 100 and measured up to `now` for the current period. Counting runtime tests as time on battery is intentional (ADR-0004).
- **Report outage window:** `api.rs:271-275` starts the query one UTC day early, so outages after local midnight in UTC+ zones are included. Stats load 62 days of outages, which is enough for 30 days and for the current month.
- **HTML escaping:** the device name, generator, title, KPI labels and notes all go through `esc`, and every other cell is numeric or a formatted date. Everything is in element content or double-quoted attributes, so not escaping `'` is fine.
- **CSV quoting:** `csv_field` quotes `,` `"` CR and LF correctly. Every field is generated (numbers, dates, fixed note strings), so there is no formula-injection surface.
- **Report saving:** the file name comes from the parsed `(year, month)` only (`report::file_name`), so there is no path injection from the month string. The directory is created, and a write error is shown in the UI. `fetch_report` caps the body at 64 MB.
- **API input validation:** `parse_month` rejects bad months, which return 400, and unknown formats also return 400. `days` and `limit` are clamped.
- **SQLite:** the migrations are transactional with a downgrade guard. `save_outage` reports a missing ID on update. `add_daily` uses an upsert in one transaction. `for_each_sample` streams rows in `ts_ms` order (the primary key), and `last_sample` and `open_outage` are correct.
- **Backfill performance:** measured in a release build: replaying 30 days of 1 s samples (2,592,000 rows, file DB in WAL mode) through the tracker and `CoverageTracker<Local>` took **about 2.0 s**. That run had 30 outages and covered 31 local days. Backfill runs once on the ingest thread, and the poller channel is unbounded, so no samples are lost during it.
- **UI:** the month combo keeps its selection unless the key list changes. The outage list is newest-first, so "interrupted" vs "in progress" holds apart from M2-5. Stats refresh every 60 s and whenever an outage starts or ends.

## Resolution (2026-11-12)
All findings fixed in the main session. 140 workspace tests pass; clippy, rustdoc and cargo-deny are clean.

| ID | Fix |
|---|---|
| M2-1 | The tracker keeps a just-ended outage as merge candidate for the whole merge window and marks it recharged only afterwards (`check_recharged`). An outage whose charge never fell below 99 % gets `recharged_at = end`, shows "not needed", and is excluded from average recharge times. Regression test at 100 % charge. |
| M2-2 | Outages store their sample count (`samples`, migration v5); resumed or reopened averages are weighted by it. Unit test (≈ 197 W instead of 63.6 W) and an e2e restart test. |
| M2-3 | `recharging_outage` only resumes the newest outage overall. Store test with an interrupted older outage. |
| M2-4 | A gap after an outage marks `recharge_unobserved` (no recharge time, excluded from averages); battery → gap → battery sets `gap_inside`. Both appear in notes, reports and CSV. Unit tests. |
| M2-5 | The UI shows "in progress" only for the newest outage within 12 h of its end, otherwise "not observed". Unit test. |
| M2-6 | `local_midnight` falls back to the first existing local hour of the day; coverage uses the same helper. |
| M2-7 | `TrackerConfig::for_poll_interval`: gap ≥ 5 × poll, energy step ≥ 2 × poll. Unit test. |
| M2-8 | Backfill writes an explicit `meta` marker last; a half-done backfill is cleared and redone. |
