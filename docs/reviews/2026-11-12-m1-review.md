# M1 review: live monitoring (2026-11-12)

Independent, read-only review of milestone M1 at commit `000da40`. Scope: `ups-model`, `ups-hid`,
`ups-source` (HID source, read-only wrapper, beeper write, mapping, simulator), `ups-store`
(samples, events, migrations), `ups-api`, `ups-collector` (main, poller, ingest, detector, API),
the dashboard and settings parts of `ups-bmc`, `hid-probe`, the installer, lint and deny
configuration, CI and ADR-0001 to ADR-0003.

## Summary

The read-only guarantee holds for the shipped code. The only device write is
`ReadOnlyHid::send_feature_report` (`pub(super)`), it is called only from `hid/control.rs`, and
it can only write `AudibleAlarmControl` = 1 or 2. On the Eaton 5E, feature report 0x14 contains
only that field, so the read-modify-write cannot touch anything else. `cargo test --workspace`
passes (all suites green, including the simulator end-to-end tests). `cargo clippy --workspace
--all-targets --locked` is clean.

No High findings. There are three Medium findings:

- The UI shows "Collector not running" every ~12 s while the UPS is unplugged (M1-1).
- The loopback API has no `Host` check, so DNS rebinding can read it (M1-2).
- The beeper write is generic rather than per model and re-sends the whole report (M1-3). This
  is safe on the 5E but not on other UPSes.

The remaining findings are Low: guard gaps, the shutdown path, docs, the installer and CI.

## Checked and fine

- **Read-only guarantee (apart from M1-3/M1-4):**
  - `ReadOnlyHid` is the only `open_path` caller, and its `HidDevice` field is private.
  - `send_feature_report` is `pub(super)`, and `control::apply` is its only caller (grep).
  - `hidapi::ffi` is private in hidapi 2.6.7, and `unsafe_code = "deny"` rules out raw `HidD_SetFeature` through `windows-sys`.
  - All nine crates have `[lints] workspace = true`, and `disallowed_methods = "deny"`.
  - `deny.toml` bans rusb, nusb, libusb1-sys, async-hid and hidapi-rusb.
- **Beeper write:**
  - The field must be a non-constant Feature field.
  - `Field::insert` rejects values outside the logical range and buffers that are too short.
  - The report is re-read and the value verified after the write, and only the verified payload is cached.
  - The 5E's report 0x14 contains only `AudibleAlarmControl` (descriptor bytes `85 14 05 84 09 5a … b1 82`).
- **HID mapping and units:**
  - The volt and watt unit codes match the fixture (`67 21 d1 f0 00`, `66 21 d1`), and the CGS −7 exponent correction is right.
  - Seconds and hertz codes are right.
  - Negative runtimes are filtered out.
  - `extract` is bounds-checked, so a short or garbled report yields `None`, not a panic.
  - `buf.get(1..n)` handles `n == 0`.
  - The poller disconnects on any read error and reconnects every 3 s.
- **SQLite:**
  - Each migration runs in its own transaction together with its `user_version` bump.
  - A newer schema is refused.
  - WAL plus `synchronous=NORMAL` are set, and readers use separate read-only connections with a busy timeout.
  - History bucketing is at least 1 s, and the API clamps `points` to 1–5000 and `minutes` to 30 days.
  - The retention prune runs hourly.
- **API input validation and CSRF:**
  - Every POST requires a JSON body (so a CORS preflight is needed) and rejects `Origin`.
  - The WebSocket rejects `Origin`.
  - `assumed-load` is range-checked (1–2000 W, and NaN or infinity are rejected).
  - Query parameters are clamped.
  - A non-loopback `--bind` is refused (with an e2e test).
  - Binding happens before the device is touched, which gives a single instance.
- **Concurrency:**
  - The HID handle is owned by the poller thread, and setting changes are serialized through the control channel between polls.
  - Ingest is the single writer.
  - Status `RwLock` poisoning is tolerated.
  - On broadcast lag, the client gets a fresh full status.
  - WebSocket sessions are cut by `shutdown_timeout`, so `ingest.join()` can finish.
- **UI:**
  - Data counts as stale after 10 s.
  - The beeper switch is disabled while a change is in progress, is reverted on failure, and is enabled only when connected, fresh and capable.
  - The "below range" load display and the user estimate work.
  - Network calls run off the UI thread.
- **Autostart and installer:**
  - The `Run` value path is quoted (with a test), and the value is removed on uninstall.
  - The install is per-user with no admin rights.
  - User data is kept on uninstall.
- **CI:**
  - Actions are pinned to SHAs and permissions are `contents: read`.
  - Clippy, tests and docs run on Windows and Linux, plus an MSRV check and cargo-deny.
  - The toolchain is pinned and matches `rust-toolchain.toml`.
- **Verification run for this review:** `cargo test --workspace` (all pass) and
  `cargo clippy --workspace --all-targets --locked` (clean), both built into a separate
  target directory. No hardware access.

## Resolution (2026-11-12)
All findings fixed in the main session. 140 workspace tests pass; clippy, rustdoc and cargo-deny are clean.

| ID | Fix |
|---|---|
| M1-1 | The live WebSocket repeats the status every 3 s (`HEARTBEAT` in `api.rs`), so a quiet collector (UPS unplugged) is no longer mistaken for a dead one by the UI's 10 s timeout. |
| M1-2 | Router-wide middleware `local_clients_only`: the `Host` must be `127.0.0.1`, `localhost` or `[::1]` with the bound port, and `Origin` is refused on every route. e2e test `refuses_foreign_host_names`. |
| M1-3 | `control::supports` refuses a beeper field that shares its feature report with any other non-constant field. Unit test with a synthetic descriptor (beeper + `Test`). ADR-0003 documents it. |
| M1-4 | `DeviceInfo::open_device` and `HidApi::wrap_sys_device` added to `clippy.toml` (the latter with `allow-invalid`, as it exists only on some backends). |
| M1-5 | The collector also stops on Windows close, sign-out and shutdown signals, and on `POST /api/v1/shutdown`. The installer calls it (via `curl.exe`) before falling back to `taskkill`. The start event notes when the previous run didn't stop cleanly. e2e test checks the graceful stop. |
| M1-6 | Settings whose caller timed out are dropped instead of applied later. Shutdown joins the poller and ingest with deadlines. |
| M1-7 | The UI remembers the newest event ID; after a reconnect it notifies events missed in between (up to 5 min old). |
| M1-8 | Without `ACPresent`, `Discharging = false` now maps to `OL` (unit test). |
| M1-9 | `recent_events` skips unknown event kinds instead of failing (unit test). |
| M1-10 | ADR-0001 (amended by ADR-0003, `ReadOnlyHid` path, clippy coverage), ADR-0002 (who starts the collector, notifications in the UI), ADR-0003 (deliberate deviations for the beeper) corrected. |
| M1-11 | Silent installs start UPS-BMC (`--minimized`) after installing, so monitoring resumes. |
| M1-12 | CI job "release build + installer (Windows)" builds the release binaries and the installer with Inno Setup. |
